# Deploy and release

Backend: **Render** (free web service, from `BE/Dockerfile`) + **Neon** (free Postgres).
App: signed APK published on **GitHub Releases** by GitHub Actions.

## 1. Database on Neon (once)
1. Neon dashboard → New project (region: Singapore / ap-southeast-1, close to Render Singapore).
2. Connection details → turn **Connection pooling off** and copy the connection string.
   It looks like `postgresql://user:pass@ep-xxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require`.
   The backend accepts it as is (it adds the asyncpg driver and SSL itself).

## 2. API on Render (once)
1. Render dashboard → **New → Blueprint** → choose the `Vahan-Khata` repo. Render reads `render.yaml`.
2. It asks for the secret values (they live only in Render, never in git or chat):
   - `DATABASE_URL`: the Neon string from step 1
   - `COMPANY_NAME`, `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `ADMIN_NAME`: the first owner login
     (used only while the users table is empty)
   - `SECRET_KEY` is generated by Render.
3. Deploy. On start the container runs the migrations, creates the company and the owner, and loads the place list.
4. Check `https://<service>.onrender.com/health` → `{"status":"ok"}`.
5. Every push to `main` deploys again (autoDeploy).

Keep it awake: on cron-job.org create a job that calls `https://<service>.onrender.com/health` every 13 minutes
(the free service sleeps after 15 idle minutes; the first request after sleep takes about a minute).

Backups: for now Neon's own restore (history window of the free plan). A nightly encrypted dump can be added later.

## 3. GitHub settings for APK releases (once)
Repo → Settings → Secrets and variables → Actions.

| Kind | Name | Value |
|---|---|---|
| Variable | `API_BASE_URL` | the Render URL, e.g. `https://vahan-khata-api.onrender.com` |
| Secret | `ANDROID_KEYSTORE_BASE64` | output of `base64 -w0 FE/android/app/upload-keystore.jks` |
| Secret | `ANDROID_KEYSTORE_PASSWORD` | `storePassword` from `FE/android/key.properties` |
| Secret | `ANDROID_KEY_PASSWORD` | `keyPassword` from `FE/android/key.properties` |
| Secret | `ANDROID_KEY_ALIAS` | `vahan_khata` |

**Back up `FE/android/app/upload-keystore.jks` and `FE/android/key.properties`** (Google Drive / pen drive).
They are not in git. Without them a new APK cannot update the installed app; every phone would have to
uninstall and install again.

## 4. Publish a new app version
```bash
git tag v1.0.1
git push origin v1.0.1
```
GitHub Actions runs the tests, builds a signed APK for 64-bit phones and adds it to Releases.
Use a higher number each time (v1.0.2, v1.1.0 ...).

## 5. Install on a phone (family)
Send this link on WhatsApp (always the newest version):
`https://github.com/Jaydip591/Vahan-Khata/releases/latest/download/VahanKhata.apk`

1. Open the link on the phone; the APK downloads.
2. Open the download. If Android asks, allow **Install unknown apps** for Chrome / Files.
3. Tap **Install**. Later versions install over it the same way; the data stays on the server.

First switch from the old test build: the test build was signed with a different key, so uninstall it once
before installing the release APK. Send any "not sent" entries first.
